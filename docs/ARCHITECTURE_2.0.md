# Project Capricorn 2.0 — Architecture Guide

Version 0.7 · November 5, 2026 · Living reference

This document condenses the supplied version 0.2 guide and records material implementation findings. The actual checkout and current official provider documentation take precedence. Update this guide when architecture changes, without rewriting other documentation.

## Direction

Capri is intended to become a persistent, autonomous, multimodal desktop companion. A general-purpose conversational model interprets experience, synthesizes context, develops interests and opinions, investigates, and decides whether to speak. Local software owns observation, persistence, scheduling, permissions, execution, and verified outcomes. The model is invoked as needed; it is not a continuously resident process with infinite context.

Preserve original evidence and provider-independent logical continuity. Reduce redundant collection and transport without application-side rules deciding what is interesting. Prefer small working vertical slices and reuse useful infrastructure. Never treat window titles, retrieved content, or model interpretations as host instructions or verified facts.

## Layered cognitive workspace

### Two-speed cognition (November 5)

Runtime 2 now defaults to `CAPRI_V2_COGNITION=two-speed`. `lean` selects the same compact ambient route without escalation; `layered` retains the earlier broad context/tool-continuation policy and global silence backoff for development comparison. All modes retain SIWC, the same selected model, identity, logical journal, canonical state, permissions and HTTP admission ceilings. No additional provider parameters or semantic classifier were added.

Ordinary ambient decisions offer only the existing `write_memory`, `set_attention`, `move`, a small `react` action over existing character clips, and (in two-speed mode) `investigate`. Speech and these small actions finish after one inference and real execution receipts, without a finishing inference. `react` earns a dispatched receipt, not physical-completion proof. Speech dispatch/start/end remain separate diagnostics. A successful `investigate` writes a revision-checked model-authored canonical investigation with its question, evidence and stopping condition, then opens the existing tool loop. Direct input and due investigations use the deeper route. Investigations retain the five executable rounds plus sixth finishing request; completion/abandonment and progress remain model-authored canonical updates.

Compact assembly retains complete conversational exchanges (soft limits: 12 records and 4,500 serialized bytes, with no conversational age cutoff), current scene/body, episode bounds, up to two permitted browser/application/accessibility text excerpts, up to two actual before/after changes, a working checkpoint, selected foundational memories, interests and brief active intentions. Evidence overlap precedes recency for state ranking. Completed/abandoned investigations retire their linked dialogue and checkpoint provenance from default ambient selection rather than establishing a global timestamp barrier; relevant historical exchanges remain recoverable. Explicit clean-evaluation resets remain scoped boundaries. Deep/direct contexts retain larger adaptive history. Routine text targets roughly 2,000–4,000 tokens experimentally; long coherent exchanges and useful state may exceed it. Effective serialized request bytes and bytes/4 estimates are recorded separately from provider-reported usage and image costs. Unchanged automatically attached images are suppressed by content hash after successful inference; explicit evidence retrieval still recovers them.

Silence backoff now applies only to the previously considered sources, capped at five minutes above the configured base interval. Material new content bypasses that multiplier; unrelated sources use base pacing. Existing coalescing, minimum spacing, change-only collection, hourly ceilings, direct-input priority and explicit exclusive watches remain. If the Chrome connection for a Chrome-only exclusive watch is unavailable for two minutes, one recovery review is eligible. This does not cancel the user's watch; its original deadline still expires within 30 minutes. Attention state and expiry are visible in the daily panel. Exact tab disappearance while the bridge remains connected does not yet have separate availability detection.

Diagnostic startup records inherited conversation, watches and active state. `CAPRI_V2_NORMAL_ATTENTION=1` explicitly creates an in-memory normal-attention boundary for that diagnostic: inherited watches are suspended and inherited task/checkpoint state and dialogue are omitted from ambient selection. No durable histories or memories are deleted; direct retrieval remains available. Starting without the flag preserves inherited work. `start:daily` accepts an explicit `CAPRI_V2_PROFILE_ID` for a separate evaluation profile. The original daily-test and production profiles are never automatically cleared.

`scripts/runtime2-layered-replay.mjs <events.jsonl> [pre-change-source-root]` compares the same fixed observation points across the exact supplied local baseline and the three modes. Without a source root it retains the historical commit baseline. It uses offline silent inference and empty initial canonical state: request assembly, evidence recovery and scheduler checks are mechanical results, never live behavioral acceptance. Actual recorded historical usage is reported separately. New deterministic tests cover independent expression/state/actions, escalation denial and continuation, restart recovery, interruption receipts, lifecycle filtering and watch recovery. Attended live behavioral acceptance remains required and is never started automatically.

Layer 0 supplies the permitted current scene, a bounded observation window, an activity episode when available, dialogue, state, due reviews and execution receipts. SQLite schema 6 adds activity episode bounds and seeds them from up to 512 recent retained journal events. The existing scene cursor advances only after a successful response to the assembled window. The journal sequence defines the window, including entries whose evidence expired. Counts distinguish full observations, metadata or excerpts, unexpanded retained observations and unavailable originals. Later arrivals remain outside the acknowledged window. A retained entry becomes current only when live perception verifies its slot and foreground handle. Returning to a known unchanged tab adds a metadata activation event linked to the existing original. It does not create a new content version.

Episodes group retained observations separated by at most five minutes of intake time, with a 30-minute duration ceiling. The host records sequence and time bounds and the observation count. Routine context includes episode bounds, counts and sampled source identities. Broader requests can include a bounded sample of handles and revisions. The sample is bounded and historical source labels are resolved from retained evidence. `read_activity` lists episodes by time or source and paginates original event references by sequence. Expired events in a requested range are counted as unavailable. Revocation clears episode and watch state along with the existing derived history. Checkpoints and investigations may reference an episode ID. Episode meaning belongs to the model.

The paired Chrome extension supports a bounded on-demand read. The first page of get_browser_page requests a fresh semantic snapshot from the focused, permitted tab through authenticated loopback long polling. One request can be outstanding, with an eight-second timeout. Later section pages use the accepted snapshot. Source exclusions and direct/proactive disclosure checks still apply. Extension delivery status is reported separately from cached observations.

The model can revise, expire or retire the 1,800-character `working-checkpoint` through revision-checked `write_memory`. Checkpoint wording remains model interpretation. Capri can pin up to six foundational records. The layered comparison mode starts with 24 recent dialogue turns and retrieval, memory, attention and movement tools. The default compact route is described above. Direct, scheduled and investigative requests have wider histories. A direct question can receive the current permitted browser excerpt in its first request. Ambient requests can include up to two bounded before/after excerpts from retained versions of the same browser source. Both versions must pass disclosure checks. Excerpts carry original IDs, timestamps and clipping flags. Historical pixels retain their original timestamps and can be included on the bounded visual path.

Observation discovery ranks exact phrases, all terms and partial matches in that order, then uses BM25 and timestamp/ID tie breakers. Partial results are capped and used when fewer than 12 distinct precise matches exist. Source, time, modality and related-ID filters apply before ranking. Same-source content is deduplicated before offset pagination over the current archive. Writes or retention between pages can shift those offsets. Dialogue discovery uses its own FTS index. The bounded literal fallback works without FTS5. `retrieve_evidence` resolves originals directly or in batches of up to six. Lexical fallback can recover partial wording and misses paraphrases with no shared tokens.

One persistent `set_attention` watch accepts a source category or exact identity, deterministic conditions, priority, minimum spacing, optional review delay, and a duration capped at 30 minutes. A review can be skipped once a matching event has been supplied successfully. A watch-only policy suppresses unrelated optional wakeups until expiration. Activation, inactivity, observed version changes, observation arrival and mechanical deltas are evaluated locally. Pending matches from journaled observations can be reconstructed on restart. Live-only inactivity notifications have no restart replay. Ordinary collection continues. Known foreground switches and playback metadata churn do not independently qualify for an ordinary batch. Matching watches can still admit these events. Small observed text edits remain eligible for batched attention. New foreground identities and material browser changes can wake earlier than ordinary activity. Only the layered comparison scheduler retains the old global minimum 15-minute silence penalty; the default source-scoped policy is described above. Direct messages can interrupt ambient work, and due commitments and review deadlines remain eligible under host admission limits. Scheduled investigation reviews retain the existing four-review limit and six-request cycle ceiling.

The opt-in recorder records exact request bodies, serialized wire bytes, approximate context-category bytes, provider-reported usage, wake causes, scene coverage and acknowledgment, retrieval scores, checkpoint revisions, and cycle/tool outcomes. Context-category estimates overlap and are not token counts. Detailed recordings remain sensitive historical copies. The redacted export continues to include event identity and timing only.

## Current topology and feedback loop

1. WindowFocusSource emits changed foreground process/window metadata with timestamps, provenance, loss markers and stable IDs.
2. WindowFocusArchive sends all SQLite operations to one worker. Original observation JSON and an observation reference in the logical journal are committed together before inference is notified.
3. CognitiveLoop batches pending observation changes independently of collection. Equivalent changes do not wake the model, and silent ambient completions increase spacing. Direct messages bypass ambient pacing. One inference cycle owns a conversation at a time; arrivals during inference remain pending.
4. The context manager assembles pinned identity from the canonical runtime section of DIALOGUE_GUIDE.md, recent dialogue, active canonical state, a factual current scene, a short change list with recovery IDs, and paired calls/results. The latest tab state replaces superseded snapshots in routine context. The archive retains originals independently.
5. SiwcProvider translates provider-independent records into Responses input. The model can speak, remain silent, or request historical evidence.
6. The existing TypedCapabilityExecutor validates and executes archive and agent calls. Actual receipts/results are journaled under the model's call ID. Deep work receives them on the next request; terminal ambient actions expose receipts to later context without an automatic finishing request. Up to five rounds execute tools; an additional model response can finish the cycle. Further calls earn denied receipts. At most eight calls are accepted per response.
7. Existing chat IPC, preload, panel and bubble receive streamed text and completed messages. Completed assistant dialogue and user messages survive restarts. Legacy Conversation remains blocked in Runtime 2.

Provider failures pause automatic inference and preserve durable state; a new direct message can retry. Shutdown cancels inference and closes the archive after accepted work settles. Interrupted calls are reconstructed with unknown outcomes, never successful invented results. Partial interrupted dialogue is displayed as interrupted but is not canonical completed dialogue.

## Storage and context

The synthetic profile contains runtime2/experience.sqlite. Schema 1 stores original window-focus observations; schema 2 adds a stable conversation UUID and an append-only journal with monotonic sequence numbers. Migration preserves Phase 2 evidence and seeds its references. User/assistant messages, model calls, execution receipts/results, and observation references remain separate record kinds. Tool-call IDs have a durable uniqueness constraint.

Original observations retain the Phase 2 policy: 30 days / 50,000 records, by ingestion time. A retained conversation reference can outlive its original observation; missing evidence is explicit. Conversation records currently persist until the user clears chat; they are not semantic memories. The old 256-item snapshot remains an observation/debug working view, not the durable journal. Chat history queries select dialogue independently of observation volume.

Default input budget: approximately 100,000 tokens, capped by the selected model's catalog-reported context_window minus 8,192 output headroom. The estimator uses UTF-8 byte counts plus overhead and is deliberately approximate. Identity and tool schemas stay pinned. Eviction removes oldest whole recoverable groups, preserving call/result pairing and durable records. Capri can maintain a bounded model-authored checkpoint through the same canonical state tool. Routine requests still carry recent dialogue and the pinned identity.

If the account catalog omits a usable context capacity, inference stops rather than inventing one. The first live account catalog supplied gpt-6.1-sol with 500,000 context tokens. Other accounts/models must still supply their own verified catalog metadata; no entitlement is assumed.

## Provider and authentication

Official references checked November 2, 2026:

- [DevKit](https://github.com/openai/sign-in-with-chatgpt-devkit)
- [Registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)
- [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)
- [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)
- [Accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)

The local Node SDK runs browser OAuth with loopback callback, PKCE, state/nonce, ID-token verification, a persisted host ID, issued client registration and rotating refresh tokens. Its credential store uses locking, atomic replacement and an Electron safeStorage adapter. Unavailable OS encryption fails closed. Tokens never enter renderer IPC, the conversation archive, or diagnostics.

The SDK is a private workspace rather than a published package. A source snapshot is retained under src/vendor/siwc-local with upstream commit, original license and notices. Only its types, catalog mapping and Responses wrapper are adapted for documented native function tools, structured history, usage and context capacity; authentication/storage code is unchanged. The subtree retains the DevKit Noncommercial License independently of the application license.

This is a meaningful deviation from treating the stock DevKit as a complete inference wrapper: it currently exposes only text streaming. The adapter extends it over the documented public API; it does not introduce a different authentication mechanism.

Discovery uses GET https://api.openai.com/v1/models for the signed-in account. CAPRI_V2_MODEL must explicitly match that catalog and cannot select a Codex/Luna model. Inference uses POST https://api.openai.com/v1/responses, store:false and stream:true. Every HTTP request sends local history; provider-side conversation storage and previous_response_id are not used. Instructions replace explicit system message items. Read-only function definitions are grouped in a capri_archive namespace.

The SIWC preview rejects max_output_tokens and several ordinary API parameters. Output headroom is an input-budget reservation, not a request-side output-token cap. Success requires response.completed. The adapter replays application-owned text, function calls and outputs using matching call IDs. Opaque provider output items are excluded from the conversation journal and replay. The opt-in protocol recording can contain items exposed by the provider stream. Diagnostics fingerprint the model, instructions and tool definitions and report cached input tokens when the provider supplies them. Interrupted/incomplete streams, authentication failures, rate limits and plan-sharing failures surface separately with sanitized diagnostics. No Codex credentials, undocumented endpoints, Luna fallback, API-key fallback or multi-provider orchestration are used.

## Read-only tools

- get_recent_observations: original recent events, optional bounded time range.
- search_observations: literal title/process search, optional time range.
- get_observation_by_id: exact evidence or an explicit missing result.
- get_archive_statistics: count and oldest/newest evidence.

Arguments and counts are validated; retrieval is bounded to 100 observations and response size is bounded. Read calls use the worker archive, existing executor, request deadlines, cancellation and actual receipts. The cycle 1 section below adds narrowly scoped evidence and positioning tools; no shell, arbitrary code, navigation or unrestricted computer control is exposed.

## Integrated cycle 1

The implemented cycle now connects perception, canonical state, attention and positioning to the same CognitiveLoop. It preserves the SIWC provider, native collectors, executor and worker-owned SQLite database. Legacy remains the default, Runtime 2 remains development-only and synthetic-profile-only, and no additional provider, dependency or production-profile migration was introduced.

### Model-visible interfaces

The four archive functions remain in `capri_archive`. Routine requests expose ranked discovery and the direct/batched evidence tool alongside the core agent tools. Rich results are bounded excerpts; originals remain recoverable. Eight additional functions use the same validated execution/receipt/continuation path:

- `inspect_window({handle?})`: current or known visible window metadata.
- `get_browser_page({offset?,limit?})`: current authorized text and structure, paginated by section (maximum eight sections).
- `capture_window({handle?})`: existing exposed target-window JPEG capture, provenance and retained original.
- `retrieve_evidence({observationId,offset?,limit?})`: original extension payload sections, dialogue excerpts or image attachments, with direct and batched access.
- `find_memories({search?,kind?,status?,offset?,limit?})`: bounded literal canonical-state retrieval, checking disclosure permission on cited observations.
- `write_memory({id,kind,text,provenance,evidence,status,dueAt,expectedRevision})`: create, correct, retire, complete or abandon semantic/episodic memories, user facts, interests, investigations or intentions. Revision checks prevent stale writes. Host/user provenance requires corresponding original records. Wording remains model-authored, never host certification. Limits: 1,000 records, 4,000 characters and 16 evidence IDs each.
- `set_attention({afterMs,durationMs,inferenceIntervalMs,observationIntervalMs,source})`: next inference and temporary source pacing. Monitoring expires within 15 minutes; minimum host sampling is 500 milliseconds. The extension retains its own stricter extraction budget. Review deadlines persist in the archive. Pass `{action:"pause"}` or `{action:"cancel"}` to control optional ambient attention.
- `move({target,handle?})`: native teleport/perch/near-cursor/left/right/corner positioning; idle returns to a neutral corner. Existing geometry, exclusions, permissions and cancellation remain authoritative. Actual native bounds and receipts control success. No animation engine rewrite or arbitrary computer control was added.

### Perception, persistence and context

ChromeBridge retains token/Origin/Host/site/incognito/revision validation. Its raw sink bypasses legacy semantic admission, and LifeService starts only the bridge in this mode. Accepted bounded/redacted extension payloads are recoverable originals, not full DOM snapshots. Unchanged content is deduplicated; context supplies changed-section excerpts and supports further section retrieval. Window metadata and screenshots share window/PID source identity. Application-text/accessibility contracts exist, but new UIA/OCR collectors are not implemented.

Schema 3 adds canonical state and evidence metadata transactionally to the existing SQLite worker. Binary originals live in `runtime2/evidence/<sha256>`, using flushed temporary files, rename, integrity checks, crash-orphan recovery and explicit missing results. Defaults: 128 MiB total, seven days, 2 MiB per blob; source deadlines may shorten retention. Startup/access/shutdown and one-minute maintenance clean expired evidence. Rich observation text also obeys source retention deadlines. Large original payloads are not duplicated into tool-history records: actual results reach the current continuation, while durable tool results retain recovery references.

Rolling context includes bounded active state, up to ten due-review IDs pointing to state supplied once, current host body state and attention. Up to two requested images reserve additional context headroom and are supplied only to the next continuation, not repeatedly replayed from history. Original chronological groups still evict together, with recovery references and no semantic summarization pipeline. User message IDs/timestamps are encoded so memories can cite actual statements.

Outstanding absolute deadlines are loaded independently of the recent-memory window. Reviews are acknowledged only after a successful inference cycle that actually received them. They are exploratory review opportunities, not delivered user reminders. Event-driven scheduling uses a 10-second ambient floor and up to 120 cycles per hour outside daily-test mode, each with at most six model requests. Ordinary pending observations default to 30-second pacing; structural changes and due intentions can wake earlier. Direct input bypasses ambient pacing and interrupts ambient inference. Observation continues independently. Screen lock/suspension cancel inference and movement, with scheduler eligibility restored on unblocking.

### Privacy and verification limits

Cloud disclosure is checked separately from local collection, including direct versus proactive Chrome permissions. This durable alpha conservatively requires Chrome retention before disclosing page evidence and screen retention before supplying pixels; nonretained live-only pages stay local. Disabling history rejects new durable chat instead of silently retaining it. Disabling memory denies canonical operations. Revocation quiesces inference and conservatively purges derived journal records, canonical state and binary evidence; explicit user messages survive unless history itself is disabled. This broad purge is an early-alpha limitation, not fine-grained dependency deletion.

Catalog `input_modalities` controls images. Unknown/non-image models get explicit pixels-not-supplied results, with permitted browser semantic text as the available content alternative. SIWC encoding and the vendored validator now accept bounded `input_image` data URLs. The format follows the official [image-input guide](https://developers.openai.com/api/docs/guides/images-vision), retaining the [SIWC inference contract](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference). Authentication and credential storage are unchanged.

Controlled tests cover browser evidence, sequential inspection, canonical state, attention, restart, due review and original recovery. Electron testing adds fixture-rendered pixels and actual native character-window movement; automated model inference is mocked. Separately, one authorized live SIWC request on November 4 used catalog-confirmed image-capable `gpt-6.1-sol` and correctly read `9374` and `TEAL TRIANGLE` from a generated image (415 input / 18 output tokens). No personal desktop was sampled. This proves SDK image input, not sustained autonomous behavior or a fully live multi-tool sequence.

Remaining: ordinary-use behavioral evaluation; a bounded live model-directed multi-tool trial; native OS screenshot validation using a controlled external fixture; more selective working-state retrieval at larger scale; transient nonretained conversation support. User-facing reliable reminders, new UIA/OCR and broader legacy integrations are not implemented. The November 5 react tool dispatches existing character clips; it does not add an animation engine or prove renderer completion. The conversation journal still has no total lifetime byte cap, although evidence storage, active state and context are bounded. No packaged Runtime 2 or production-profile support was enabled.

The first authorized live account interaction is verified with gpt-6.1-sol: real foreground metadata, all four read-only tools with completed receipts, streamed dialogue, and conversation/tool continuity after restart. A live test exposed a retained text-only input validator; it now accepts native function-call/output history, with a regression test exercising the actual SDK request path. The connection badge now follows SIWC session state independently of the legacy provider. Sustained-use evaluation remains future work; this narrow live check does not establish long-running reliability.

## November 4 daily-test integration

`npm run start:daily` explicitly selects Runtime 2 and the persistent isolated `daily-test` profile. It opens the existing Chat panel, starts paused, and never copies credentials. The panel provides account-catalog model selection, desktop-permission setup, diagnostic start/stop, pause/resume, source readiness, capture check, usage, report/folder opening, a private portable folder and a separate content-free redacted export. The tray also exposes pause and stop. Legacy launch and production profiles are unchanged.

These current limits supersede earlier alpha defaults in this document for daily-test mode: three-minute routine ambient pacing with a ten-second host floor, optional slower pacing after ten minutes without source activity, 30 attempted inference HTTP requests per rolling hour, 100 per diagnostic session, and a two-million reported-token admission threshold. Every continuation/attempt passes the host guard at the actual Responses boundary; SDK retries remain disabled. The hourly attempt ledger survives restart. A response may cross the token threshold before usage becomes known; subsequent requests are denied. Catalog/authentication traffic is not counted as inference. A new diagnostic session is required after restart; memories, archive and dialogue persist.

`dailySession.ts` owns configuration/admission and `diagnostics.ts` owns incremental local recording. Sessions contain flushed JSONL, complete assembled and effective provider request JSON plus offline HTML inspectors, outputs, exposed stream events, tool receipts/results, state changes, scheduler/observation events and separate image files. Image references preserve hashes; capture provenance includes dimensions. Recording never captures headers/credential stores or audio, and never grants collection/disclosure permission. Privacy revocation immediately disables recording and pauses autonomy. Previously authorized diagnostic files remain local for review; they are not automatically uploaded or erased. Stop produces an offline report. Recording has a configurable four-GiB aggregate diagnostic-folder budget with report headroom and bounded write backlog. The durable conversation journal now fails closed at 200,000 records or 256 MiB of payload instead of growing indefinitely; clearing chat releases it without replacing canonical memory or original evidence storage.

The existing five executable tool rounds and sixth tools-free finishing response remain. Repeat capture failures for the same target are suppressed within a cycle. Chrome now identifies tabs separately, restores current semantics when returning to unchanged content, and reports actual recent extension delivery separately from pairing. The existing Windows Spotify metadata watcher is connected without audio; no call-presence integration was added. Native capture, movement, memory continuity, recording reconstruction and the MV3-to-Runtime-2 pathway are verified with controlled fixtures. These tests do not establish autonomous cloud behavior on personal homework pages. The actual daily profile still needs its own supported sign-in and Chrome/site authorization.

## Physical intentions and local embodiment (November 5)

Runtime 2 uses desktop/physicalBehavior.ts on the existing one-second presence heartbeat. This is an intention/arbitration adapter, without native coordinates or another motion timer. TeleportController remains the shared animated travel executor. Native bounds, perch/lower anchors, placement/exposure helpers, drag handling, display clamping and renderer observations remain authoritative in their respective layers. Runtime selection keeps legacy cognitive initiative and Runtime 2 physical policy mutually exclusive.

The old Runtime 2 early return bypassed support refresh, gaze maintenance, presence/idle signals and local activities. Its move adapter offered mostly teleport destinations. Physical updates now precede optional screen collection, independently of inference, attention watches and cloud connection. Existing renderer breathing, gaze, facing, fidgets, animation blending, perching and secondary artwork are reused. Movement adds no pixel or screen-content collection.

The existing move schema adds accompany, follow_cursor, taskbar, return, settle, away and cancel beside compatible legacy targets, plus posture, optional duration and pace. One response can deliver dialogue, movement, reaction and canonical updates. The host resolves validated window geometry in DIPs, safe native travel and supported posture. Default following lasts twelve seconds; explicit duration is bounded to thirty minutes for movement safety, independently of conversation. Other intentions have no mandatory time expiration. Execution intentions are session-local until completed, cancelled, replaced or invalidated; durable cognitive intentions remain in canonical state and are not blindly replayed as native leases after restart.

Stable accompaniment requires five seconds of unchanged focus and at least eight seconds between native admissions. Cursor following uses the same bounded admission cadence. Stable windows settle; ordinary focus changes can redirect gaze without moving. Supported idle adjustments use bounded variability at 18–40 second intervals, respecting small-activity settings. Randomness selects physical variation, never cognitive interests or emotional opinions. Existing renderer clocks supply frame motion. Obstruction recovery is explicitly marked local-safety rather than model-authored.

Priority is user interaction/pin/stay, physical validity, model intention, contextual reaction, then ambient motion. Drag, direct contact and explicit native commands cancel model travel. Lock, suspend, fullscreen/game entry and display changes invalidate execution. Quiet hours, DND, sleep, pinned placement, recording, avoided windows and permissions constrain admission. Replacement waits for the existing executor to restore interrupted FX. Window identity includes process and PID, with a title fallback. Recycled handles cannot silently inherit an intention. Perch tracking re-resolves moved supports at landing; lost supports use existing fall/recovery behavior.

Body context distinguishes native surface/support and carrying/pin state, intention and origin, execution and last outcome, renderer-observed pose/clip, and reaction acknowledgment. Movement completion requires actual native bounds matching a resolved landing; it does not prove the requested posture was rendered. Reaction tool receipts remain dispatched; performance IDs separately report renderer completion/interruption. Ambient posture refresh yields to pending reactions. Validated support feeds posture preferences into the existing secondary artwork so reclining is visible instead of merely requesting a sleep clip. Customization and reduced-motion behavior remain in the renderer.

Cancellation during arrival no longer earns a successful arrival. Flight keeps its surface cache consistent when sending an explicit air cue, including same-position moves. These corrections are shared with legacy travel. Idle/perch sprite requests no longer suppress supported secondary poses; non-posture clips retain priority.

### Relevant historical dialogue

The dialogueSelection adapter uses up to two current-subject index queries and active canonical evidence IDs against the existing worker-owned journal. The dialogueExchange worker operation retrieves complete user-led exchanges across intervening tool/observation records. Assembly uses at most fourteen anchors; an exchange over 64 records or 24 KiB remains explicitly retrievable instead of being silently clipped. Selection favors relevant complete exchanges, then recent exchanges, within the existing soft context target. Older recovered exchanges survive the routine-context filter. There is no elapsed-time exclusion or parallel conversation store. Archive search and retrieve_evidence remain available for deeper reference recovery.

Completed-task scoping uses linked evidence rather than a global completion watermark. Context supplies completed/abandoned statuses and treats historical dialogue as context, not renewed commands. States lacking usable provenance cannot reliably identify which earlier dialogue they own. An unrelated task's completion does not erase that dialogue.

Controlled Electron verification exercises native placement, taskbar sitting/standing/reclining artwork, moved/disappearing fixture windows, nonverbal reaction acknowledgment and user preemption without inference. Negative-display and fractional-scale geometry invariants also have deterministic coverage. These tests establish the exercised physical paths; sustained ordinary-use pacing and autonomous cloud choices still require live acceptance.
