# Reliability and context selection (1.5.3)

This builds on the 1.5.2 audit in FUNCTIONAL_RELIABILITY.md. No new dependency, memory store, tracking database, model-selection call, speech schedule or movement policy was added.

## Corrections

- Retiring an ephemeral Codex thread previously stopped the shared stdio server. Supported servers now unsubscribe that thread. Source conversations reuse an ephemeral thread in memory, including intervening ordinary exchanges; their handles never enter the persisted session checkpoint. Private turns remain disposable. Dependencies accumulate so revoking either source retires the whole dependent thread. Older protocols retain the safe shutdown fallback.
- Chat previously discarded every source-backed assistant quote. Newly delivered quotes can be recalled as dated dialogue only when source retention is authorized and current permissions allow it. Invalidation permanently withdraws their inference eligibility while preserving the visible transcript. Legacy quotes without eligibility remain excluded. Source evidence is never promoted to a current fact through dialogue history. Nonretained source continuity stays in the ephemeral native thread.
- Location detection no longer treats words such as “go,” “been,” “home,” or “lately” as sufficient location intent. Personal whereabouts questions receive explicit fresh proximity, tentative/corroborated visits, confidence, chronological timestamps and incomplete-coverage metadata. Unrelated chat no longer receives fresh location records through the generic assembler. Available public area names describe the coarse lookup tile; coordinates remain excluded.
- Public lookups previously filled a cache without reclassifying the initiating fix. Their result now reclassifies the latest eligible report without adding an independent sample. Same-tile reports share in-flight results. Newer positions, expiry, revocation and receiver generations reject obsolete callbacks. Dwell and boundary standards are unchanged.
- Ambient context selects observations associated with the current target or an active interest, rather than every recent window. Subjectless ambient decisions no longer load arbitrary profile facts. Expired interest labels stay in internal suppression bookkeeping but leave inference context. Episode search now includes original observations as well as delivered opinions and interpretations.

## Measurements and behavioral checks

A synthetic eight-window ambient fixture retained its relevant violet-control memory and unchanged 9,958-character system guidance. Total content fell from 11,790 to 10,684 characters. Actual Luna CLI replay input fell **6,395 → 6,080 tokens (4.9%)**, with 3,072 cached tokens in each request. Both first outputs chose silence; the earlier payload retained a curiosity and the later one did not. Single observations do not establish latency or sustained-quality gains.

The sampled direct-chat base prompt stayed at 11,084 characters. Native requests retain character instructions at thread creation and send changed application blocks plus a bounded first-turn handoff. Memory learning still supplies the current batch, comparison memories, relationship/working state, selected episodes and attributed taste sources; its full comparison snapshot was retained to avoid weakening correction and duplicate detection. No whole-application token reduction is claimed.

Live synthetic checks covered fresh, tentative, historical, stale, unrecognized and unavailable phone evidence. The original historical seeding fixture required a clock correction to preserve corroboration through retention cleanup; both runs are recorded locally. One initial fresh-location answer denied usable evidence, while subsequent answers named the place cautiously. Location phrasing remains imperfect.

A packaged native exchange recalled Zinnia Observatory after arithmetic, then lost that quote after revocation while keeping the same backend process. A separate restart test retained ordinary native history. A memory probe selected a three-day-old violet-control opinion without the dinner episode or expired question; its generated explanation paraphrased the original reason loosely. A realistic observation sequence made one specific remark, skipped unchanged evidence without inference, silently resolved the curiosity on changed evidence, and made no expired-interest call. This demonstrates the sequence, not sustained naturalness.

## Verification and limits

Final verification: typecheck, production/NSIS build, and all **863 unit tests** passed (the final full run used serial files to avoid contention). The final packaged selection passed four checks covering native source continuity/revocation, phone ingestion/retrieval, retained subjects and profile restart; two unrelated native cases were intentionally excluded from that selection after passing earlier restart/large-context checks. All 67 packaged production files matched the build, with no profile/secret files in the archive. Installed executable and bundled package both report 1.5.3; the installed archive matches the tested package. All 33 stopped-profile files were unchanged before launch, and the normal-profile smoke retained 40 approved memories. Desktop, Start Menu and legacy Electron shortcuts target the installed app with `dev.capri.buddy`; no matching taskbar shortcut was present.

The four previously reported unit failures were obsolete assertions: three expected the pre-compaction guide and one required uninterrupted reclining despite the later lower-ledge pose cycle. Their replacements check the current guidance and supported pose variation. The memory-cap test now seeds all but the last slot and verifies the actual add/reopen/overflow boundary, avoiding 1,000 synchronous rewrites. A parallel broad run also hit an unrelated automatic-movement timing failure; final results are recorded in the delivery report.

The expanded packaged selection exposed four existing failures in continuity, routine-touch admission and dialogueGrounding fixtures. All four reproduced against installed 1.5.2. They remain unresolved; no fully green desktop suite is claimed. Honcho behavior was left unchanged because this cycle found no concrete provider-recall or learning defect. Source history remains permission-dependent, public lookup coverage varies, and unobserved routes, activities and stops remain unknown.
